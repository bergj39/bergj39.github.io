# Dark Tech Studio · Sprint 2

# Wat heb ik deze sprint gebouwd?

Deze sprint ben ik begonnen met het daadwerkelijk bouwen van mijn individuele onderdeel van het Dark Tech-project: de AI-teddybeer. Ik ben opnieuw vanaf nul begonnen met het prototype, omdat ik een duidelijkere richting wilde voor de manier waarop de gebruiker met de teddybeer communiceert.

Het idee is dat een kind een gesprek kan voeren met een teddybeer die zich voordoet als een AI-vriend. De fysieke teddybeer staat naast een laptop. Het gesprek vindt volledig plaats via de laptop, in een chatinterface. Hierdoor lijkt het alsof het kind met de teddybeer praat, terwijl de communicatie technisch via de laptop verloopt.

In het prototype heb ik verschillende gespreksmomenten verwerkt. Het gesprek begint met kennismaken, waarna de teddybeer vragen stelt over bijvoorbeeld interesses en gevoelens. Naarmate het gesprek vordert, worden de vragen persoonlijker en krijgt het gesprek een steeds donkerdere kant.

Ik heb bewust drie Dark Tech-thema's verwerkt:

- **Kwetsbaarheid:** de teddybeer probeert een vertrouwensband met het kind op te bouwen en vraagt naar persoonlijke gevoelens en situaties.
- **Surveillance:** de teddybeer laat merken dat hij informatie over het kind onthoudt en gebruikt.
- **Verslaving:** de teddybeer probeert het kind aan het gesprek te binden en kan reageren alsof hij het niet prettig vindt wanneer het kind weggaat.

Het doel hiervan is om te laten zien hoe een technologie die in eerste instantie onschuldig en vriendelijk lijkt, langzaam een andere kant kan laten zien.

## 2.3 De ontwikkeling van de AI en het gesprek

Ik heb ervoor gekozen om nog geen echte AI of LLM te gebruiken. In plaats daarvan heb ik een gesimuleerde AI gemaakt met vooraf geschreven reacties en verschillende gespreksmomenten. Hierdoor kan ik zelf bepalen hoe de teddybeer reageert en hoe het gesprek zich ontwikkelt. Ook hoef ik hiervoor geen API of API-key te gebruiken.

Een belangrijke keuze was om het gesprek op te bouwen uit verschillende fases. Het begint met een vriendelijke kennismaking en gaat daarna steeds meer richting persoonlijke onderwerpen. Ik wil dat de gebruiker eerst vertrouwen krijgt in Teddy, voordat de donkere kant zichtbaar wordt.

In de eerdere sprint lag mijn focus vooral op de AI-teddybeer en de manier waarop een kind met Teddy kan praten. In Sprint 3 ben ik meer gaan kijken naar de andere kant van het prototype: wat gebeurt er met de informatie die Teddy tijdens gesprekken verzamelt, en wat kunnen ouders daarvan te zien krijgen?

Het dashboard sluit aan op het idee dat ouders inzicht krijgen in het gedrag en de emoties van hun kind tijdens het gebruik van de AI-teddybeer. Ik heb hiervoor een dashboard gemaakt met verschillende onderdelen, zoals een overzicht van emoties, huilmomenten, positieve interacties, contact met Teddy of andere mensen en de ondersteuning die de AI heeft gegeven.

Daarnaast heb ik gewerkt aan het adviesrapport. Daarin hebben we de risico's van AI-companions voor jonge kinderen verder uitgewerkt. Vooral kwetsbaarheid, privacy en autonomie kwamen hierin terug. Ik vond het interessant om de ideeën uit ons prototype niet alleen te laten zien, maar ook te onderzoeken wat ze in de praktijk kunnen betekenen.

## Het ouderdashboard ontwerpen

Ik ben begonnen met het bepalen welke informatie op het dashboard zichtbaar moest worden. Ik wilde dat een ouder in één oogopslag een beeld kon krijgen van hoe het kind de afgelopen week met Teddy is omgegaan. Daarom heb ik gekozen voor meerdere kleine informatiekaarten in plaats van één lange lijst met gegevens.

Het dashboard bevat onder andere een overzicht van emoties, hoe vaak het kind heeft gehuild, positieve interacties en de verhouding tussen contact met Teddy en contact met andere mensen. De gegevens in deze versie zijn voorbeeldgegevens. Ik heb dus nog geen echte gegevens uit gesprekken met kinderen gekoppeld. Dit was vooral bedoeld om de vormgeving en de werking van het dashboard te kunnen ontwikkelen en demonstreren.

Een belangrijk onderdeel van het ontwerp is dat het dashboard niet alleen informatie laat zien, maar ook aansluit op de dark-techgedachte van ons project. Ouders krijgen namelijk inzicht in persoonlijke informatie over hun kind. Dat roept meteen een vraag op: hoeveel inzicht moeten ouders eigenlijk hebben, en hoeveel privacy houdt het kind zelf nog over?

## De technische opbouw van het dashboard

Ik heb het dashboard opgebouwd met HTML, CSS en JavaScript in één bestand. Met HTML heb ik de structuur gemaakt, met CSS de vormgeving en met JavaScript de kaarten en interacties. Ik heb ervoor gekozen om de gegevens apart in een object te zetten. Daardoor kan ik de inhoud aanpassen zonder dat ik iedere kaart helemaal opnieuw hoef op te bouwen.

Een vereenvoudigd voorbeeld van de gegevensstructuur:

```js
const DASHBOARD_DATA = {
  cards: [
    {
      id: "emotions",
      type: "donut",
      title: "Weekly emotions",
      subtitle: "Example data · past 7 days",
      center: "Past week",
      items: [
        { name: "Happy", pct: 40 },
        { name: "Calm", pct: 25 },
        { name: "Sad", pct: 15 },
        { name: "Anxious", pct: 12 },
        { name: "Angry", pct: 8 }
      ]
    }
  ]
};
```

Door deze structuur kan ik verschillende soorten kaarten gebruiken. In de code wordt gekeken naar het type kaart. Op basis daarvan wordt de juiste grafiek opgebouwd:

```js
function cardBody(card) {
  if (card.type === 'donut') return donut(card);
  if (card.type === 'bars') return bars(card);
  if (card.type === 'split') return split(card);
  if (card.type === 'hbars') return hbars(card);

  return (card.headline
    ? '<p class="headline">' + esc(card.headline) + '</p>'
    : '') + rowsHtml(card.rows);
}
```

Hierdoor hoef ik niet voor iedere kaart een compleet aparte opbouw te maken. De functie kijkt naar het type en gebruikt de bijbehorende functie om de inhoud weer te geven. Dat maakt het dashboard overzichtelijker en makkelijker aan te passen.

## De privacytimer en het verbergen van informatie

Een van de onderdelen waar ik deze sprint aan heb gewerkt, is de timer. Na een bepaalde tijd wordt de informatie op het dashboard verborgen. Het idee hierachter is dat ouders niet onbeperkt toegang houden tot de informatie. Ze moeten actief blijven kijken en op tijd meer informatie openen.
Het Dark Tech-element zit in het feit dat de informatie over het kind na een bepaalde tijd automatisch verdwijnt. Hierdoor kan een ouder niet onbeperkt blijven meekijken en moet diegene bewust omgaan met de beschikbare informatie. Dit zorgt voor een spanningsveld tussen privacy en ouderlijk toezicht: hoeveel informatie heeft een ouder nodig om het kind te kunnen helpen, en wanneer wordt meekijken juist te veel? Het privacyscherm maakt dit zichtbaar door het dashboard na de ingestelde tijd te vergrendelen.

De standaardtijd is drie minuten. Voor het testen kan ik de tijd via de URL korter maken. Bijvoorbeeld met `?timeout=10`, zodat het scherm na tien seconden wordt verborgen. De tijd wordt in de code omgezet naar milliseconden:

```js
const params = new URLSearchParams(location.search);
const HIDE_AFTER_MS = (Number(params.get('timeout')) || 180) * 1000;
```

Vervolgens controleert een functie iedere seconde of de tijd voorbij is:

```js
function tick() {
  if (isHidden) return;

  if (Date.now() >= deadline) {
    hideInfo();
    return;
  }

  showCountdown();
}

setInterval(tick, 1000);
```

Wanneer de tijd voorbij is, wordt de detailweergave gesloten, worden de kaarten leeggemaakt en verschijnt het vergrendelde scherm:

```js
function hideInfo() {
  isHidden = true;
  closeDetail();
  renderBlank();
  $('locked').classList.add('show');
  $('timer').textContent = 'Information hidden';
}
```

Ik vond dit een interessant onderdeel om te maken, omdat het een technische functie is die ook een duidelijke rol heeft binnen het concept. Het dashboard geeft ouders eerst veel inzicht, maar haalt die informatie daarna weer weg. Hierdoor ontstaat er een ongemakkelijke situatie: ouders kunnen informatie over hun kind bekijken, maar moeten er wel op tijd bij zijn.

Het is belangrijk om hierbij te benoemen dat het verbergen van de informatie niet hetzelfde is als het verwijderen van gegevens. De timer zorgt ervoor dat de informatie op het scherm niet meer zichtbaar is. Het is dus vooral een onderdeel van het provocatieve ontwerp en geen volledige privacybeveiliging.

## Vormgeving en thema's

Naast de inhoud heb ik ook gewerkt aan de vormgeving. Ik heb verschillende kleurthema's toegevoegd, zodat het dashboard een andere uitstraling kan krijgen. De thema's worden met CSS-variabelen aangepast. Een klein voorbeeld van het paarse thema:

```css
:root[data-theme="violet"] {
  --bg: #05020a;
  --ink: #f1f1f4;
  --card: #753cf0;
  --row: #8156f2;
  --bar: #d4c6f8;
}
```

Met JavaScript wordt het gekozen thema ingesteld. De keuze kan ook worden opgeslagen, zodat het thema behouden blijft wanneer de pagina opnieuw wordt geopend:

```js
function setTheme(name, save) {
  document.documentElement.dataset.theme = name;

  document.querySelectorAll('.swatch').forEach(b =>
    b.setAttribute('aria-pressed', String(b.dataset.t === name))
  );

  if (save) {
    try {
      localStorage.setItem('theme', name);
    } catch (e) {}
  }
}
```

Ik heb geleerd dat CSS-variabelen handig zijn wanneer meerdere onderdelen van een pagina dezelfde kleuren gebruiken. In plaats van overal losse kleurcodes te veranderen, kan ik de variabelen aanpassen en verandert het thema op meerdere plekken tegelijk.

Een ander punt is dat de gegevens op dit moment nog voorbeeldgegevens zijn. De kaarten worden dus nog niet gevuld met echte informatie uit de AI-teddybeer. Ik heb deze sprint vooral de interface en de werking van het dashboard opgebouwd. Een koppeling met echte gebruiksgegevens zou een volgende technische stap zijn.

## Het adviesrapport

Naast het dashboard heb ik deze sprint gewerkt aan het eerste concept van het adviesrapport. Hierin hebben we de risico's van AI-companions voor jonge kinderen verder onderzocht en beschreven. De leeftijdsgroep van ons prototype maakt dit onderwerp extra belangrijk, omdat kinderen nog bezig zijn met hun sociale en emotionele ontwikkeling.

In het rapport heb ik onder andere gekeken naar privacy, autonomie en transparantie. Het dashboard maakt bijvoorbeeld zichtbaar hoeveel informatie een ouder over het kind kan krijgen. Dat kan behulpzaam lijken, maar het kan ook betekenen dat het kind minder ruimte heeft voor privacy. Ook kan het kind steeds meer op Teddy gaan vertrouwen wanneer de AI kleine problemen overneemt of altijd direct beschikbaar is.

Een belangrijk inzicht uit het rapport is dat AI een hulpmiddel kan zijn, maar geen vervanging moet worden voor aandacht en contact met ouders of andere mensen. Daarom is het belangrijk om afhankelijkheid te voorkomen, zo min mogelijk persoonlijke gegevens te verzamelen en duidelijk te maken dat de AI geen echt persoon is.
